# 2026-10-20

## file-j（macOS 12 双栏文件管理器）—— 主体完成

技术栈：Tauri 2 壳（Rust 仅框架）+ Vue 3 / Tailwind 3.4 / TS 前端 + Go 1.26.9 sidecar 业务后端；
前后端通过 loopback WebSocket JSON-RPC 通信；全部持久化走 YAML（无数据库）。

### 关键决定
- **交互方式**：Go 后端由 Rust 以 sidecar 方式拉起，绑定 `127.0.0.1:0`，首行 stdout 输出握手 JSON
  `{type:"ready",port,token,...}`；前端用 token 连 `/ws`。不把业务路由放进 Rust（否则 Rust 承担业务）。
- **统一文件抽象**：`fsx.Provider`（Stat/List/Open/Create/MkdirAll/Remove/Rename/Chmod/Chtimes/Home）
  本地盘与 SFTP 同一接口，传输引擎因此只有一份代码覆盖 本地↔本地 / 上传 / 下载。
- **第三方库**：`golang.org/x/crypto/ssh` + `github.com/pkg/sftp`（远程）、`gorilla/websocket`（IPC）、
  `gopkg.in/yaml.v3`（配置）、`golang.org/x/sys/unix`（statfs 剩余空间）。
- **密钥不进 YAML**：macOS Keychain（`security` CLI）存密码，YAML 只存 `credentialRef`；
  钥匙串不可用时降级为内存并向前端返回 warning。
- **macOS 12 兼容**：Tailwind 固定在 3.4（v4 需 Safari 16.4）、Vite `build.target: ["safari15"]`、
  `bundle.macOS.minimumSystemVersion: "12.0"`。

### 验证方式（可复用）
- Go：`cd backend && go test ./...`（config/remote/transfer/app 四包，含进程内真实 SSH+SFTP 服务器
  `internal/testutil/sshd.go`）。
- 前端：`npx vue-tsc --noEmit`、`npx vite build`。
- UI 视觉回归：headless Chrome `--remote-debugging-port=9333 --enable-unsafe-swiftshader`，
  CDP 脚本量取 `getBoundingClientRect()` 校验列头/数据行对齐（列头需带 `border-l-2 border-l-transparent`
  才能与行内 2px 选中条对齐）。
- 真实链路：`./src-tauri/target/debug/file-j`，日志出现 `backend listening addr=127.0.0.1:<随机端口>`
  与 `client connected` 即证明 Rust→Go 握手 + 前端 WS 打通；配置落在 `~/Library/Application Support/file-j/`。

### 踩坑
- `cargo build` 会把 sidecar 复制到 `target/debug/file-jd`，调试时它**优先于** `src-tauri/binaries/` 被加载，
  改了 Go 代码只跑 `pnpm backend:build` 不生效，需重新 `cargo build` 或手动覆盖该副本。
- 在受限沙箱里启动 GUI，进程会继承沙箱：`~/Library` 下 rename 返回 EPERM、窗口截图可能拍不到。
  `writeYAML` 已加「rename 失败 → 原地重写」兜底。
- 配置目录里的 `*.tmp` 残留是 rename 被拒时的副产物，正常环境不会出现。

### 菜单栏改名 FileJ + 全中文（同日晚）
- `tauri.conf.json`: `productName`/窗口 `title` 改 `FileJ`（`productName` 决定 Info.plist 的 CFBundleName/CFBundleDisplayName，
  即打包后菜单栏显示名）；**未改** `identifier`、Go 侧配置目录 `file-j`、sidecar 名 `file-jd`，因此用户数据与打包布局不变。

### 界面缺陷修复：窗口拖动 + 设置页控件（同日晚）

**1. 窗口不能拖动（三个叠加原因）**
- `style.css` 用的是 `-webkit-app-region: drag`——这是 Electron 属性，WKWebView 不实现，从来没生效过。
- `Toolbar.vue` 的 `data-tauri-drag-region` 是**裸属性**：Tauri 脚本语义为「只有直接点到该元素本身才拖」，
  点 header 的任一子元素（如 `flex-1` 占位）都不触发。正确值有 `deep`（子树全部生效，自动跳过 button/a/input/select/label/
  contenteditable/tabindex≠-1/交互 role）和 `false`（阻断）。
- `capabilities/default.json` 缺 `core:window:allow-start-dragging`（`core:default` **不含**它，也不含
  `allow-internal-toggle-maximize`），invoke 被 ACL 拒绝且静默。
- 结论：这类窗口能力问题先查 `~/.cargo/registry/.../tauri-<ver>/src/window/scripts/drag.js`，别信 CSS。
  macOS 语义在脚本里已内置：双击 → mouseup 且未移动才 `internal_toggle_maximize`。

**2. Toggle 滑块溢出轨道**
- `absolute` + 只给 `top` 不给 `left` 时，`left` 取静态位置；`<button>` 的 UA `text-align: center`
  使静态位置落在轨道水平中心（实测 30px 轨道 → `left: 15px`），再叠加 `translate-x-[14px]` 就右溢 13px。
- 修法：显式 `left-[2px]`，位移改 `translate-x-0 / translate-x-[12px]`（30-2×2-14=12），并补 `box-border p-0 border-0`。
- 量取手法：vite 起 fixture 页读 `getBoundingClientRect()`，不要靠肉眼估。

**3. 下拉菜单 3D 感**
- 原生 `<select>` 由平台绘制 menulist button（渐变+内斜面+高光边），CSS 的 background/border 基本无效，
  `.dark` 的 `color-scheme: dark` 只会把斜面变成亮边，故深色下更扎眼。
- 修法：`select.field { -webkit-appearance:none; appearance:none }` + data URI 内联 chevron
  （`background-position: right 7px center`、`padding-right: 20px`），箭头色按主题给两份（data URI 里用不了 currentColor），
  `select.field option` 补齐暗色行底色。data: 在 CSP `img-src` 白名单内，Safari 15 可用。


## 顶栏改版：删品牌 + 红绿灯垂直居中（Toolbar.vue / lib.rs）

**前端**：`Toolbar.vue` 删掉 brand 区块（渐变方块 + `file-j` 文字）及其后的竖分隔线，保留
`pl-[80px]` 作为红绿灯让位，其余子项都 ≤28px 高、由 `items-center` 统一压到中线。

**macOS 红绿灯对齐（关键数据，实测）**
- `titleBarStyle: Overlay` + `hiddenTitle` 下，AppKit 把三色按钮放在 28pt 标题栏里，
  距窗口顶边 **14pt**（close 按钮 h=16、在 button group 内 y=6，group 填满 `NSTitlebarContainerView`）。
- 52px 顶栏中线是 26pt，所以默认偏高 12pt——这就是“顶栏内容与红绿灯不齐”的全部原因。
- 按钮锚定在 titlebar container 的**下边**：container 高度 +N，按钮就下移 N，WebView 不受影响。
  故目标 container 高度 = `52/2 + anchor`，anchor = `group.y + button.y + button.h/2` = 14
  → **container 高度 40**（默认 28）。
- 反面教材：用 `convertRect:toView:nil` 换算按钮位置会少 6pt（据此算锚点得出 34 的错值，
  像素上一动不动），正确做法是按 frame 链逐级相加。
- 实测手段：`screencapture -x` + PIL 找红点行数得中线，再与顶栏背景色行范围比对；
  `-R` 局部截图会被抢焦点，需在同一条命令里 kill → 启动 → sleep → 截图。
- AppKit 在 resize / 缩放 / 主题切换时会重排标题栏，故这些事件里要重新对齐（幂等：差值 <0.5 直接返回）。
- Rust 侧依赖：`objc2` + `objc2-core-foundation`（feature `objc2` 才给 CGRect/CGPoint 的 Encode），
  只用 `msg_send!` 操作 AnyObject，不引入 objc2-app-kit。
